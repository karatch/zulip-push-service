# Zulip to Telegram Secure Push Gateway

Высокопроизводительный асинхронный интеграционный шлюз (микросервис) на Python для мгновенной пересылки корпоративных push-уведомлений из чат-пространства **Zulip** в персональные чаты сотрудников в **Telegram**.

Проект разработан с учетом строгих корпоративных стандартов безопасности (Enterprise Security), полностью изолирует конфиденциальные данные от утечек и работает в асинхронном безаварийном режиме 24/7.

---

## Ключевые особенности и архитектура

* **Защищенная двухфакторная аутентификация (2FA / OTP):** Исключен риск шпионажа и брутфорса чужих ID. Привязка аккаунта происходит через ввод корпоративного email. Шлюз сверяет адрес со списком разрешенных доменов, находит сотрудника на сервере Zulip по реальному полю `delivery_email` и отправляет ему случайный 4-значный одноразовый пароль (OTP) в личные сообщения внутри Zulip.
* **Deep Linking (Переход к сообщению в 1 клик):** Все входящие пуши содержат прямую экранированную кликабельную ссылку (`urllib.parse.quote`). При тапе по ссылке пользователь мгновенно перемещается к нужному треду или сообщению в интерфейсе Zulip.
* **Контроль сетевого трафика (Throttling):** Использование асинхронных семафоров (`asyncio.Semaphore(20)`) ограничивает количество одновременных запросов к Telegram API, защищая шлюз от получения `HTTP 429 Too Many Requests` при массовых обсуждениях в каналах на сотни подписчиков.
* **Режим Fail-Fast (Таймаут 3 сек):** Сетевые запросы жестко ограничены таймаутом в 3 секунды, что предотвращает зависание асинхронной очереди при временных сбоях на стороне Telegram.
* **Мгновенный Graceful Shutdown:** Использование асинхронных событий (`asyncio.Event`), изоляция синхронного слушателя событий Zulip в выделенном пуле демон-потоков (`ThreadPoolExecutor`) и системное прерывание `os._exit(0)` гарантируют, что приложение мгновенно завершает свою работу с первого клика с успешным `Exit code 0`.
* **Безопасность конфигурации (.env):** Все критические секреты и настройки (токены, префиксы, домены) полностью изолированы от кода и считываются из переменных окружения в соответствии с методологией Twelve-Factor App.

## Инструкция для сотрудников: Подключение уведомлений

Чтобы начать получать мгновенные пуши в Telegram без необходимости держать открытым тяжелое мобильное приложение Zulip, выполните 3 простых шага:

### Шаг 1. Запустите бота
1. Найдите корпоративного бота в Telegram и нажмите кнопку **Старт** (или введите команду `/start`).

### Шаг 2. Укажите корпоративный email
1. В главном меню бота нажмите кнопку **🔐 Привязать Zulip ID**.
2. Введите вашу рабочую почту (например, `alex@company.com`).
3. Бот автоматически проверит ваш адрес в белом списке организации и сгенерирует секретный код верификации.

### Шаг 3. Введите код подтверждения (OTP)
1. Откройте приложение или веб-версию **Zulip**.
2. Перейдите во вкладку **Личные сообщения (Direct messages)**. Найдите чат от имени нашего корпоративного бота — там будет находиться 4-значный цифровой код.
3. Скопируйте этот код, вернитесь в Telegram и отправьте его боту.

🎉 **Успешно!** Интеграция активирована. Теперь новые сообщения из всех публичных стримов Zulip, в которых вы состоите, будут мгновенно дублироваться вам в Telegram.

## Требования к боту Zulip (Для администратора)

Для того чтобы уведомления корректно приходили пользователям из всех каналов, учетная запись бота Zulip, прописанная в конфигурационном файле `zuliprc`, должна иметь соответствующий уровень доступа. Существует три варианта настройки:

* **Вариант 1 (Generic Bot) — Ручной:** 
  Если это обычный бот, его необходимо вручную (или скриптом) **добавить (подписать) на все каналы (стримы)**, сообщения из которых планируется транслировать пользователям. Если бота нет в канале, он физически не сможет перехватить событие.

* **Вариант 2 (Администратор/Служба) — Повышенные права:** 
  Вы можете повысить роль существующего бота в панели управления Zulip до административной службы организации, у которой есть право автоматического чтения всех публичных стримов без явной подписки на них.

* **Вариант 3 (Outgoing Webhook или Администратор/Служба) — Идеальный вариант ⭐:** 
  Создать в панели администратора Zulip бота с типом **Outgoing webhook** или сразу настроить его как **Администратора/Службу**, у которой есть полный доступ к просмотру всех публичных стримов организации. Это избавит вас от необходимости добавлять бота вручную в каждый новый создаваемый канал — он будет автоматически «видеть» и обрабатывать сообщения со всего пространства Zulip.

## Инструкция по развертыванию для администратора

### 1. Подготовка конфигурационных файлов `zuliprc`, `.env`

Подготовка конфигурационных файлов
В корневой папке приложения должны находиться два файла конфигурации.

Создайте шаблон окружения **`.env`**:
```env
# Токен вашего Telegram-бота (от @BotFather)
TELEGRAM_BOT_TOKEN=8967776105:AAF...ваш_токен...

# Разрешенные корпоративные домены для регистрации (без @, через запятую)
ALLOWED_COMPANY_DOMAINS=company.com,://company.com

# Кастомный префикс для формирования диплинков (опционально)
NTFY_TOPIC_PREFIX=zulip_tg_push
```
*Убедитесь, что файл `.env` добавлен в `.gitignore` вашего репозитория!*

Положите рядом стандартный файл авторизации **`zuliprc`** вашего Generic-бота с правами Администратора организации Zulip:
```ini
[api]
site = https://company.com
email = push-bot-bot@://company.com
key = abcdefghijklmnopqrstuvwxyz123456
```


2. Запустите шлюз:

## Настройка фоновой службы Linux (Systemd)

### 2. Сборка бинарного файла через PyInstaller

Приложение компилируется в один исполняемый файл, который содержит интерпретатор Python и все необходимые зависимости. Сборку необходимо проводить **строго на той же операционной системе** (и архитектуре), где планируется запуск приложения (например, на целевом Linux-сервере).

1. Перейдите в каталог проекта, активируйте ваше виртуальное окружение и установите необходимые зависимости:
   ```bash
   pip install aiogram aiohttp zulip pyinstaller magic-filter
   ```
2. Выполните команду для сборки проекта в один файл с учетом скрытых импортов `aiogram`:
   ```bash
   pyinstaller --clean --onefile \
     --name=tg-integration \
     --hidden-import=aiogram \
     --hidden-import=aiogram.dispatcher \
     --hidden-import=aiogram.filters \
     --hidden-import=aiogram.fsm.storage.memory \
     --hidden-import=magic_filter \
     --hidden-import=aiohttp \
     run.py
   ```
   *После успешного завершения сборки готовый бинарник появится в директории `dist/tg-integration`.*

### 3. Развертывание службы через systemd

Для обеспечения непрерывной работы 24/7 настройте шлюз как системную службу. Запуск от пользователя `root` запрещен из соображений безопасности.

1. Создайте рабочую директорию проекта и перенесите туда файлы:
   ```bash
   mkdir -p /home/user/zulip_bridge
   cp dist/tg-integration /home/user/zulip_bridge/
   # Перенесите файл zuliprc в эту же папку
   ```
2. Дайте бинарному файлу права на исполнение:
   ```bash
   chmod +x /home/user/zulip_bridge/tg-integration
   ```
3. Создайте конфигурационный файл службы:
   ```bash
   sudo nano /etc/systemd/system/zulip-integration.service
   ```
4. Вставьте в него следующую конфигурацию (замените `user` и пути на ваши реальные):
   ```ini
   [Unit]
   Description=Zulip to Telegram Integration Service
   After=network.target

   [Service]
   Type=simple
   User=user
   WorkingDirectory=/home/user/zulip_bridge
   ExecStart=/home/user/zulip_bridge/tg-integration
   Restart=always
   RestartSec=5
   StandardOutput=journal
   StandardError=journal

   [Install]
   WantedBy=multi-user.target
   ```
5. Зарегистрируйте и запустите службу:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable zulip-integration.service
   sudo systemctl start zulip-integration.service
   ```

### 4. Настройка ротации и очистки логов journald

По умолчанию системный журнал `journald` может занимать значительный объем диска. Чтобы логи приложения не переполнили сервер, необходимо настроить их ротацию по размеру.

#### Автоматическая ротация (Рекомендуется)
1. Откройте файл конфигурации системного журнала:
   ```bash
   sudo nano /etc/systemd/journald.conf
   ```
2. Раскомментируйте или добавьте в секцию `[Journal]` следующие параметры для жесткого ограничения логов (например, до 500 МБ):
   ```ini
   [Journal]
   SystemMaxUse=500M
   SystemMaxFileSize=50M
   SystemKeepFree=1G
   ```
3. Перезапустите службу логирования для применения настроек:
   ```bash
   sudo systemctl restart systemd-journald
   ```

#### Ручная очистка логов (Прямо сейчас)
Если на сервере скопилось много старых логов и вам нужно принудительно освободить место, оставив только последние 500 МБ данных, выполните команду:
```bash
sudo journalctl --vacuum-size=500M
```

### 5. Полезные команды для администрирования

* **Просмотр логов в реальном времени ("живой поток"):**
  ```bash
  sudo journalctl -u zulip-integration.service -f
  ```
* **Проверить текущий статус работы процесса (Active/Running):**
  ```bash
  sudo systemctl status zulip-integration.service
  ```
* **Перезапустить сервис (например, после изменения `zuliprc`):**
  ```bash
  sudo systemctl restart zulip-integration.service
  ```
* **Остановить службу (выключить процесс прямо сейчас):**
  ```bash
  sudo systemctl stop zulip-integration.service
  ```
* **Отключить автозапуск (дезактивировать запуск вместе с ОС):**
  ```bash
  sudo systemctl disable zulip-integration.service
  ```
  *Примечание: Команда `disable` не останавливает уже запущенный процесс, она лишь отменяет его автоматический старт при следующей перезагрузке сервера.*
* **Полное отключение (и остановить, и убрать из автозапуска):**
  ```bash
  sudo systemctl stop zulip-integration.service && sudo systemctl disable zulip-integration.service
  ```
